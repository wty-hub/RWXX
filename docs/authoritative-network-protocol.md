# RWXX 权威服务器新协议

当前源码中的应用版本为 `2.2.0`，新模式使用候选协议 `7`。独立服务器、客户端 CLI 和大厅“实验新协议：创建 / 加入”入口均已接入 v7；原版联机兼容协议 `176` 作为独立模式保留。新模式由服务器运行完整仿真，客户端接收获准披露的时间线；房主仍能读取本机服务器的完整状态。

字段、字节编码与状态规则见 [v7 逐字节候选规范](authoritative-wire-v7.md)，离线编解码工具与向量见 [v7 参考附件](protocol/v7/README.md)，架构目标见 [PA 式架构与验收门槛](authoritative-v7-design.md)。参考附件的离线互证不能代替完整客户端联网验收。

本机独立服务器与 64 个真实 TLS 客户端、合计 128 个原生单位的检查已通过；这只证明该场景，不能外推为大规模实时容量。65,536 单位的实时性能目标尚未达标，v7 的容量、GUI 与正式发布整体验收尚未完成。

以下保留 v6 及更早阶段的运行说明、玩法范围与验证记录，版本号、测试数字和产物指纹均属于各自历史产物，不代表当前 v7 的运行方式或验收结果。历史第三方客户端格式见[协议 v6 逐字节规范](authoritative-wire-v6.md)；连接当前新模式应使用上述 v7 规范。

## 最近通过验收的 v6

该轮应用版本为 `2.1.0`，新视图协议为 `6`；其运行路径仅接受 v6，不保留新视图协议 1–5 的解析分支。原版联机兼容版本为 `176`，原版存档和回放路径独立保留。
本轮新增每秒完整状态摘要检查，已通过构建、真实引擎、120 秒 TCP 连接和虚拟屏验收。结果见 [v6 验证记录](verification/authoritative-v6-2.1.0-2026-11-07.json)，绑定冻结 JAR `23aa52f7…1465bb7`。下方 v5 及更早的测试数字、产物指纹、带宽与 GUI 结果均为历史证据。

- 服务器继续持有完整仿真，只投影当前连接获准知道的内容。世界通道改为一次静态地图初始化、完整动态 Baseline，以及带精确基线序号的 Delta；单位按新增、字段补丁和撤销传输，迷雾按整层替换或有界区间更新。
- 地图采用两阶段握手：服务端 MapOffer 提出本局公共地图的 SHA-256 key，客户端只查找并校验这一张缓存，保留在内存后回复 MapReady(true)；没有有效缓存则回复 false。命中后 MapCached 替代 MapInit，随后仍发送动态 Baseline。Hello 不带缓存列表，不一次加载全部磁盘缓存。迷雾、实体、资源、动作面板、凭据和战局历史不进入缓存。
- 动作面板使用独立 Baseline/Delta 通道。基础 Order 只保留移动、攻击移动、停止、攻击单位四种；建造、生产等统一经当前己方能力面板的 ActionIntent 执行，不保留旧的类型白名单基本指令分支。
- 目标使用显式 None/Point/Unit 标签，所有序号为正数。缺少差量基线时清除可操作状态并请求相应通道基线；重复初始化地图、非法字段和越权状态不靠重同步掩盖。
- 新本人视角回放容器为格式 2，只接纳 v6 的自包含 MapInit/Baseline/Delta，保存实际 ticksPerSecond；不接受地图缓存引用，也不解析此前新视图协议的录制格式。原版回放引擎不受此改变影响。
- 有效世界和动作面板各按单调时钟约每秒检查一次完整原始状态，使用 SHA-256 前 16 字节并隔离 WORLD/PANEL 域。静态地图、全部授权单位、迷雾和面板字段均进入摘要；无变化和终局继续检查。摘要失配先撤销操作，再以实际摘要 ACK 触发完整基线恢复，不重复发送显式恢复请求；独立 10 秒确认及恢复期限不由保活续期，显式和隐式恢复均受连续预算约束。不扩大披露范围，也不把旧基线再录成新事件。
- 桌面客户端使用 Kool 展示并进行有限状态插值，完整仿真仍只在服务器进程。独立服务器、房主自动启动本机服务器与大厅新模式入口保留。

这是实验实现。普通大厅的“实验新协议：创建 / 加入”入口与原有联机按钮分开；没有“防透视已正式验收”的产品标识。旧客户端连接到新协议端口不保证得到明确的版本识别或友好提示。

本轮验证范围：

- core 783 项、desktop 245 项测试无失败，core 跳过 1 项；77 项验收工具离线测试通过。冻结 JAR 和实际打包应用的原生入口分别通过 340 项真实引擎检查，包含 38 项基础、71 项动作、192 项升级和 39 项重连检查。原生入口在私有 headless/UIElement 环境中运行，精简运行时不含 java/keytool。
- 独立服务器与两个客户端 JVM 连续运行 120 秒。每端收到一次地图、一次世界 Baseline 和 1201 个 Delta，推进至 tick 7206；WORLD/PANEL 各检查 113 次、确认共 226 次，失配、恢复和重同步均为零。实测稳态下行约 650.5 字节/秒，含检查消息，不含 TCP/TLS。场景只有两个己方单位、一次移动和一次面板查询，不能作为大规模战斗的带宽保证。
- 每通道的一次 StateCheck 和 StateAck 各为 46 字节。每秒检查一次时，每通道上下行合计 92 字节/秒，世界和动作面板同时有效时合计 184 字节/秒；这些数字不含 TCP/IP/TLS，也不含正常差量或恢复基线。18 个合成差量场景全部重建成功，各自另外传输 12 组检查及确认。
- 本机 aarch64、Java 25 的完整摘要合成测试包含静态地图、动态状态、规范编码、字段校验与 SHA-256。1000 单位的中位耗时为 0.293 毫秒、P95 为 0.342 毫秒；65,536 单位分别为 7.828 和 8.764 毫秒。这是本机 JVM 延迟测量，不代表服务器容量或移动设备表现。
- 两个 Vulkan 客户端分别提交 1260、1290 帧，只读回放提交 570 帧且始终零输入。最终菜单 host/join API 桥接的房主、访客分别提交 2340、1140 帧，均完成选择、生产、队列扣费、取消和退款。访客实际命中地图缓存，MapInit=0、MapCached=1，省去 60,501 字节静态地图传输。
- 最终两组图形验收的虚拟屏 56、61 均已移除，只读复查与原显示配置一致。所有客户端启动静音、无 GameEngine，窗口保护未报告激活、焦点或越界，已知图像泄漏及字体错误诊断通过。这是实际 UI 路由、菜单 API 与呈现帧验收，不是大厅按钮物理点击、系统剪贴板或截图像素基准测试。前两次菜单运行因工具误判退出中的进程身份而中止，失败原记录保留；其中第一次显示清理失败的记录也保留，随后只读复查确认该屏已消失、原配置未变。
- 49 个合法、29 个拒绝向量覆盖全部 18 类消息，11 个完整摘要与独立 Python 一致，普通及 `-O` 模式互证通过。公开编解码器还读取并逐字节重编码了本轮真实地图缓存和自包含回放。资料见[协议附件目录](protocol/v6/README.md)，分发包为 `build/protocol-docs/RWXX-protocol-v6-client-spec-2026-11-07.zip`。

当前 macOS 应用为 `desktop/build/jpackage/image/macos-arm64/RWXX.app`，归档为 `desktop/build/distributions/RWXX-2.1.0-macos-arm64-desktop.zip`，内含同一冻结 JAR。原有 1217 个引擎类和两个窗口宿主类与互联基线逐字节相同；原版 1.15 双向各 600 秒的历史检查未在本轮重跑。没有安装或替换 `/Applications/RWXX.app`。

## 历史验收记录（协议 v5）

该阶段应用版本为 `2.0.0`，协议为 `5`。结果见 [v5 验证记录](verification/authoritative-v5-2.0.0-2026-11-06.json)，绑定冻结 JAR `57d035c4…8e2055`。[v5 逐字节规范](authoritative-wire-v5.md)和[更早 v4 规范](authoritative-wire-v4.md)保留为档案，不能用于当前 v6 连接。

- 冻结产物通过 340 项真实引擎检查：38 项基础检查、71 项动作、192 项升级、39 项重连及终局检查。实际生成的 macOS 应用原生入口在私有 headless/UIElement 环境中也通过同一组检查；精简运行时没有 java/keytool，固定指纹 TLS 和父管道 EOF 停服通过。
- 独立服务器与两个客户端 JVM 连续运行 120 秒，两端各收到 1202 个视图，其中 1201 个 Delta，推进到 tick 7206。每端静态地图和世界基线均只传一次，无重同步；首次传输为 72,878 字节，随后平均接收约 564.3 字节/秒。这是本张地图、两个己方单位、一次移动和一次面板查询的应用数据实测，不含 TCP/TLS 开销。
- 另有 18 个合成场景，每个重建 120 帧，覆盖 100/500/1000 单位。单位与迷雾不变时均为 50 字节/帧；单个血量字段或单格迷雾变化为 64 字节/帧；1000 单位全部仅修改 x 时为 14,050 字节/帧；整层迷雾变化为 12,155 字节/帧。流量取决于实际变化，不能把静止场景的数字当作固定带宽。
- 两个 Vulkan 客户端各提交 1260 帧，均通过实际指针/按键处理路径完成选择、生产、队列扣费、取消和退款；只读回放提交 540 帧，始终零输入。菜单 host/join API 桥接又启动独立房主、访客与服务器，房主、访客分别提交 2310、1080 帧并完成同样的动作。访客实际命中房主已保存的公开地图缓存，MapInit=0、MapCached=1；这次省去 60,501 字节的静态地图传输。

- 45 个合法向量、14 个拒绝向量覆盖全部 16 类消息；独立 Python 编解码器在普通及 `-O` 模式逐字节互证通过。相同工具也读取了本次真实缓存文件和自包含回放。公开资料见[协议附件目录](protocol/v5/README.md)，可分发 ZIP 位于 `build/protocol-docs/RWXX-protocol-v5-client-spec-2026-11-06.zip`。

该 v5 阶段 macOS 应用为 `desktop/build/jpackage/image/macos-arm64/RWXX.app`，归档为 `desktop/build/distributions/RWXX-2.0.0-macos-arm64-desktop.zip`，内含同一冻结 JAR。原有 1217 个引擎类和两个窗口宿主类与互联基线逐字节相同；原版 1.15 双向各 600 秒的历史检查未在本轮重跑。没有安装或替换 `/Applications/RWXX.app`。

## 当前玩法范围

目前限制为 Small Island、两个固定人类席位、动态迷雾、标准单位。移动、攻击与停止保留群体操作；单选己方单位请求独立动作面板，
面板包含服务器审核的建造、生产、升级、取消、集结、维修、回收、运输、地面动作与开关。模块蜘蛛的子模块通过父单位面板代理，不增发子模块实体句柄。
标准内容表覆盖 120 个具体 stock 配置、18 个原生替代和其余原生类型；目录与引用闭包完整不等于所有玩法已经验收。
协议 4 历史冻结产物的真实引擎动作检查见 `desktop/build/authoritative/phase4-final-v3-artifact-actions.json`：152 个加载类型的盘点无未闭合或不支持条目；

## 信息边界

服务器持有完整仿真；客户端不加载原始地图文件、地图脚本、完整存档或全局单位对象。
每个连接只接收公开静态地形、本人迷雾与资源、己方单位及目前获准看见的敌方单位的白名单显示字段。
Baseline 是该玩家动态视图的完整替换，Delta 只更新精确基线上的已授权字段；两者均不是整个世界的存档。客户端完整校验后原子提交重建结果，差量失配期间清除可操作状态。缺失视野、无效席位、败北或胜利等终局状态不会升级为全图观战。

生产路径使用完整冻结的 stock 目录和编译动作闭包。单位级 `CustomUnitConfig.isVisible` 只允许 `null`；
目录捕获拒绝任何非空谓词，投影视图和供视野路径也直接拒绝，不执行谓词再根据结果筛选。敌方可见性仍受独立本人 LOS 和冻结的敌方可见标志约束。
这与动作的 `isVisible/isActive` 不同：动作动态条件只可在执行阶段权威复核，未证明安全的面板状态不求值而显示 UNKNOWN。

单位句柄属于一个连接，与全局对象 ID 无关；离开视野后撤销，重新侦察时分配新的句柄。
世界基线与差量均不包含攻击目标、路径、运输乘员、隐藏对象引用、敌方资源或全世界校验和；单位撤销没有死亡原因。
无法撤销客户端已经看过的信息；保证目标是停止披露隐藏期间的新变化。

意图消息包括单调序号、引用的视图序号和已披露的单位句柄。服务器重新检查所有权、时效和目标可见性。
移动及攻击移动可以指向迷雾内坐标。攻击单位需要该连接已披露且当前仍可见的目标。
指令经现有 CommandController 执行，服务器计算寻路、伤害、资源和战斗结果。

动作查询使用独立递增序号；动作意图与普通移动/攻击共用命令序号。一个连接只保留一个选择面板，最多 128 个动作、64 KiB 独立帧，
不占用完整世界视图的 4 MiB 帧预算。动作 receipt 与当前世界 receipt 分别检查新鲜度，切换选择、换类型、失控、装载、动作撤销或终局即撤销能力。
协议 4 的历史容量测试实际往返 65,536 个唯一单位及全部 1–3 科技等级，并实测恰好 4 MiB 的视图 payload 后仍可独立读取动作面板；
该历史测试中第 65,537 个单位与多出 1 byte 的帧在读写两端拒绝，写入拒绝不留下半帧。历史 v5 的 Baseline/Delta 格式与容量检查已重新验证；群体操作上限仍为 256，不以降低单位数替代容量验证。
句柄保存真实 owner、action、queueId 和编译引用身份，不接受网络传入原 ActionId，不对网络字符串调用 ActionId.intern。
动作标题采用审核静态 key。未证明只依赖己方/公开状态的动态条件标记 UNKNOWN，允许尝试并由服务器执行时复核；不发送动态 tooltip、禁用原因或隐藏引用。

新 TCP 监听器完全独立于原 NetworkEngine 收发路径，不接受旧协议包，也不回退为旧协议。
固定席位由服务端 token 文件绑定；一个席位只允许一个活动连接。重连建立新连接代际，旧输入和旧快照不得进入新连接。
收发队列、帧、字符串、单位数量和命令速率均有上限；慢连接不能无限阻塞仿真。

默认只监听 `127.0.0.1`，本机连接允许明文。跨机器服务器必须配置 TLS，客户端必须固定服务器证书 SHA-256 指纹，
先验证证书再发送席位凭据，不因 TLS 失败退回明文。证书指纹应通过可信渠道与玩家共享，席位 token 则分别私下交付。
独立服务器管理员以及玩家自建房的房主仍能读取服务器完整状态。

## 本机运行

桌面端可直接使用普通联机大厅的新协议按钮。创建时填写对方可连接的地址和端口（例如 `192.168.1.2:5124`），程序自动生成两份独立席位凭据与固定证书指纹的 TLS 配置。
把生成的私人邀请交给另一位玩家，在“实验新协议：加入”中粘贴；不要把邀请公开发布。原版服务器继续通过原有创建、加入按钮使用。
新玩家窗口运行在独立进程中，即使普通菜单已经预热旧引擎，也不会把完整仿真带进新客户端。
房间文件保存到用户可写的数据目录 `authoritative-rooms/room-*`；显式 `launch.dir` 覆盖则使用该隔离目录，不向安装目录写入房间凭据。
房主正常关闭时等待本机服务器退出；房主异常结束时，服务器通过专用父进程管道的 EOF 自动停服。独立服务器入口不要求此管道。

下面是独立服务器管理员与命令行用法。

源码与 JAR 命令需要 JDK 25；安装包的新协议入口使用内置运行时，自动证书生成不调用外部 `keytool`。从仓库根目录运行时，建议通过 `-Dlaunch.dir=...` 指定隔离的存储目录。

先生成两个随机席位 token；服务器保存全部 token，每个玩家只获得自己的文件。不要把完整 seats 文件发给普通玩家。

```sh
python3 - <<'PY'
import pathlib, secrets
root = pathlib.Path('desktop/build/authoritative-seats')
root.mkdir(parents=True, exist_ok=True)
tokens = [secrets.token_urlsafe(32) for _ in range(2)]
(root / 'seats.properties').write_text(''.join(f'{i}={token}\n' for i, token in enumerate(tokens)))
for i, token in enumerate(tokens):
    (root / f'player-{i}.token').write_text(token + '\n')
for file in root.iterdir():
    file.chmod(0o600)
PY

./gradlew :desktop:authoritative --args='--authority-server --seats=desktop/build/authoritative-seats/seats.properties --port=5124'
```

两个客户端分别使用自己的文件：

```sh
./gradlew :desktop:authoritative --args='--authority-client --connect=127.0.0.1 --port=5124 --token-file=desktop/build/authoritative-seats/player-0.token'
./gradlew :desktop:authoritative --args='--authority-client --connect=127.0.0.1 --port=5124 --token-file=desktop/build/authoritative-seats/player-1.token'
```

为避免多个 Gradle 进程争用构建输出，长时间试玩建议先构建平台 JAR，再使用不同终端执行 `java -jar <平台JAR> <上述启动参数>`。
不要运行未经授权的性能注入环境变量或在生产数据目录中运行验收夹具。

房主入口自动启动服务器子进程并让房主作为席位客户端加入：

```sh
./gradlew :desktop:authoritative --args='--authority-host --seats=desktop/build/authoritative-seats/seats.properties --token-file=desktop/build/authoritative-seats/player-0.token --port=5124'
```

此时另一玩家连接同一个端口。跨机器测试需要显式 `--bind=<监听地址>`，客户端 `--connect=<服务器地址>`。
房主关闭客户端时结束本机服务器，不转移服务器状态到其他玩家。

跨机器运行还需要 TLS。先生成独立的密钥库口令文件，再创建服务器证书：

```sh
python3 - <<'PY'
from pathlib import Path
import secrets
p = Path('desktop/build/authoritative-seats/tls-password.txt')
p.write_text(secrets.token_urlsafe(32) + '\n')
p.chmod(0o600)
PY
keytool -genkeypair -alias rwxx-server -keyalg EC -groupname secp256r1 -dname 'CN=RWXX Server' \
  -validity 3650 -storetype PKCS12 -keystore desktop/build/authoritative-seats/server.p12 \
  -storepass:file desktop/build/authoritative-seats/tls-password.txt -noprompt
```

服务器加 `--tls-keystore=.../server.p12 --tls-password-file=.../tls-password.txt --bind=<监听地址>`。
启动日志会显示公开的证书 SHA-256 指纹，远程客户端加 `--server-fingerprint=<指纹>`。
私钥、口令文件和完整席位文件仅由服务器管理员保存。房主子进程模式同样支持这些 TLS 参数，并自动为本机房主固定该证书。

战术操作：单击选择，Shift 加选，Ctrl+A 全选，右键移动或攻击可见敌人，A 后点击攻击移动，S 停止。
单选完成的己方单位后从侧栏动作面板操作；页内数字键选择动作，翻页访问全部动作，Ctrl 加数字取消一项真实队列，Shift 为允许的航点类动作追加队列。
F/T/E 与 P/B 快捷键在新面板中选择对应能力；面板未知状态可以尝试，明确不可用状态禁止新操作，队列取消独立于当前资金。
HUD 显示资源、tick、建造进度和胜负；原游戏的完整操作界面尚未接入。
客户端使用 Kool/Vulkan 或 OpenGL 呈现；按获准状态的 tick 插值，失去视野或重同步时立即停止使用旧实体作为操作目标。

桌面设置的 Gameplay 页可配置“新协议地图缓存数量”，默认 16、范围 0..256，0 关闭缓存。命令行可用 `--map-cache-limit=N` 覆盖数量、`--map-cache-dir=/绝对路径` 指定目录；普通菜单创建的不同房间共用用户缓存目录 `cache/authoritative-maps-v6/`。新设置在下次连接时生效并裁剪超额旧缓存，按写入或使用时间淘汰最久未用项。

每次连接只在收到 MapOffer 后查找当前这一张地图，完整验证并钉在内存后才回复命中；后续磁盘文件消失不会使该引用失效。损坏或缺失缓存正常回复未命中。缓存不加载 TMX、INI 或脚本；独立地图握手的绝对 10 秒期限不会被保活延长。

连接客户端时增加 `--record-view=/绝对路径/本局.rwxview` 可录制本人收到的视图。
文件不能覆盖；磁盘错误或有界队列溢出会明确停止录制，不阻塞游戏、不把不完整文件标记为成功。
格式 2 文件自身含静态地图，即使本次连接命中缓存也不依赖外部缓存；录制只保存本人动态基线与差量，不保存瞬态动作面板。它不包含服务器存档、敌方私有状态或全图回放。观看文件时不建立网络连接，也不初始化游戏仿真：

```sh
./gradlew :desktop:authoritative --args='--authority-replay --replay-file=/绝对路径/本局.rwxview --speed=1'
```

回放为只读，速度范围为 0.25–8；当前支持线性播放，暂停与跳转尚未接入。
正常终局发送公开胜负结果并冻结已经获准的视野；终局重连不继承旧连接的战场实体或探索历史，也不会自动变成全图观战。

## 验证方式与历史验收边界

自动检查强制无界面运行。需要真实窗口的图形验收只允许在独立虚拟屏幕中执行，并从窗口创建前绑定屏幕、禁止激活与获取焦点、
启动前静音；结束后验证虚拟屏已移除且原显示配置一致。不能让常规桌面验收窗口影响前台工作。

以下虚拟屏运行描述属于协议 4 的历史产物，不是当前 v6 的图形验收。

先前最终 v3 的只读预检 `desktop/build/authoritative/kool-phase4-v2/result.json` 曾在创建前拒绝运行：主屏当时 inactive，且前次失败注册的显示器
`vendor=29561, serial=807753347` 仍在清单中。该次没有创建显示器或启动游戏 JVM，原始阻碍记录保留。
两个验收脚本按该精确 vendor/serial 组合拒绝，不依赖可能复用的 ID 50 或旧坐标，也不泛拦其他用户显示器。
本次重试前已重新只读确认主屏 active、mode 可读且该组合消失，随后分别使用本次持有的虚拟屏 51 和 53 完成验收。
最终 `desktop/build/authoritative/native-phase4-final-v3-postcheck.ndjson` 仅有物理主屏 1，显示清单与两次测试前及清理结果完全一致。
窗口保护证据为创建前绑定及事件/累积状态检查，不是独立 WindowServer 持续观察；后续重试仍不得绕过预检或改用前台屏幕。

```sh
./gradlew --init-script desktop/src/test/tools/headless-tests.init.gradle :core:test :desktop:test
./gradlew :desktop:authoritative --args='--authority-verify --output=desktop/build/authoritative/verification.json'
python3 -B -m unittest discover -s desktop/src/test/tools -p 'test_*.py'
```

验收夹具只在 `--authority-verify` 入口中设置验证场景，复用生产完整目录、冻结地图与投影器，检查隐藏状态不干扰公开消息、真实 TCP 收发、服务器指令执行和旧版本常量。
普通服务器入口不会执行这些夹具。单元测试和短场景不能替代所有标准单位、长时间对局、全部生命周期和完整安全验收。

只新增四个只读内容访问桥接类；两个窗口宿主类也未变化。旧模式的长时 GUI 对局没有在 v3 上重跑，类等价不能改写为本轮运行证据。

动作探针经过已呈现帧的普通指针/按键路径完成选择、生产、队列出现和取消退款；回放即使继承探针开关也保持零输入。
菜单此次证明房主正常关闭后服务器停止；异常强杀和父管道 EOF 因果不属于这次 GUI 运行，EOF 另有先前无窗口专项检查。
首次菜单尝试因进程身份采样不匹配失败，但游戏与虚拟屏均已清理；成功重跑没有触发重采样，不能据此确认首次错误就是 exec 竞态。

完整标准动作的实现与待验收项见[动作目录与隐私设计](authoritative-actions-design.md)；设计文字不能作为功能完成或安全验收证据。
