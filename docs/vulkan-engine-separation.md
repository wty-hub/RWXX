# 原版引擎与 Vulkan 渲染分离

2026 年 10 月 4 日保留的地图缓存、像素与上传池、文字网格复用、指针和帧节奏改动见
[Windows 快速拖图优化实现记录](windows-map-pan-optimization.md)。该记录单独列出本轮验证及实验默认状态。

Kool 桌面后端由唯一的 `RWX-engine-owner` 线程执行完整原版 `gameLoop()`。输入、模拟、HUD 和原版绘制方法都在该线程运行；绘制方法中原有的状态修改与命令创建也保留。Kool 保持 `asyncSceneUpdate=false`，只消费完成的 CPU 画面并提交 GPU。

引擎时钟不取渲染帧的 delta。沿用现有秒到原版时间的换算、上限以及 batterySaving / highRefreshRate 外层节流；没有引入统一固定 60 tick/s。联机、回放的累积器、步长协商、寻路等待和命令执行仍由原版循环处理。未载图的房间也运行外层循环，以处理网络消息。GPU 等待或窗口隐藏不暂停引擎；原版暂停和网络阻塞规则仍有效。

## 画面、输入与资源

`FrameEnvelope` 包含序号、会话世代、模拟 tick、视口及相机版本、绘制命令和资源租约。它不进入网络、存档或回放。单槽交接只替换待显示画面；完整引擎循环不会因为丢画面而省略。重复显示同一个画面复用已建世界批次，只有明确标记的性能 HUD 更新测量文本；首轮没有插值。

CPU 资源在注册时固定像素或编码字节，嵌套画面与位移效果底图递归固定版本。字体使用版本令牌及不可变测量数据；引擎不持有 GPU 字体或贴图。待消费、当前显示及 GPU 在途画面分别持有租约，实际 Vulkan fence 完成后回收。CPU 单槽、GPU 两个在途槽及有界上传缓存控制积压。

输入和会话操作按 FIFO 进入所有者队列，不合并按键、按钮或滚轮。快速按下与释放必须分别被完整原版循环观察到。结果操作发布真实异步完成结果，UI 不提前假定成功。点击同时固定所见相机及事件发生时的窗口尺寸，先按 X / Y 分别还原被拉伸的旧画面，再映射到引擎当前相机；侧栏 X 按右侧锚点及实际侧栏宽度映射，避免变成世界点击。失焦释放沿用捕获的事件上下文并进入队列。

相机在原生呈现成功后才发布：Vulkan 的 SUCCESS / SUBOPTIMAL 或可见 OpenGL 的实际交换返回会确认候选画面；取出画面、获取交换链失败和呈现失败不推进点击相机。场景释放、会话关闭及世代检查阻止迟到确认。首帧之前仍保留指针按下与释放，使用既有无相机坐标回退。

画面包固定原版 HUD 绘制阶段的布局标量及矩形，再单独记录最终绘出的小地图范围。小地图相对位置、取消选择和底部编队按钮分别映射到其实际锚点；标准动作网格按行距映射，避免以窗口高度缩放全部侧栏。特殊、全宽或滚动重排动作面板仍缺少完整精确命中验收。模组地图条目及特征在所有者线程完成后发布为不可变元数据；模组窗口取消选择拖动也进入同一所有者队列。载图、模组修改及重载串行执行，载入和暂停恢复后重置外层计时基准。

## Vulkan 和批次

- 修复旋转实例容量反置和字节寻址 `MixedBuffer` 的四倍上传。
- 两个在途槽复用常驻映射上传缓冲区，依据实际 fence 复用与销毁。
- 贴图上传并入主帧命令流，在 render pass 外准备资源，补齐 transfer / shader / vertex 同步；没有每张动态贴图后的整队列等待。
- 持久化原生管线缓存，共享着色器，静态精灵图集实例携带队伍染色、透明度、仿射变换、翻转及动画源矩形。
- 只合并相邻兼容命令。动态贴图、越界 UV、位移及不适合图集的命令沿用通用绘制路径，透明遮挡顺序保持。
- 选择超过 256 时最多预览 8 个单位的命令线，低于 192 恢复；可见单位超过 512 时省略小型地面阴影，低于 384 恢复。每个选中单位仍保留选择标记。只过滤明确标注的显示命令，本地开关默认开启。

未知自定义 GLSL 并未移植。Kool 仍报告不支持旧 ShaderProgram，原版据此关闭高级后处理和 fancy-water 路径；显式 Kool 位移命令有独立的原生实现。通用网格回退能保留已支持的命令，不能执行任意旧着色器。

上述全单位结果是 CPU 构造、更新和绘制命令烟测，不能代替 GPU 视觉、全部运输行为或各特殊动作的验收。双向联机使用 Steam 基础包中未改动的原版 1.15 引擎、网络和命令实现，以及独立的无窗口上下文适配器；原版原生桌面界面在本机缺少 x86_64 翻译环境，未完成验收。该项覆盖 136 个单位、13 种陆海空及基地类型，不代表所有形态及持续 2000 单位交战通过。10 分钟记录固定为 v4 运行包，后续点击呈现确认与 HUD 投影修正另行验证。

`CanvasFrameMetrics` 的 `acceptedPresentFps` 是 `vkQueuePresent` 成功或 SUBOPTIMAL 后的接受率，不代表物理屏幕扫描率。`producedSnapshotHz`、`freshSnapshotHz`、`simulationTicksPerSecond` 和 `repeatRatio` 分别记录引擎完成画面、实际选用新画面、模拟推进和重复显示。`RWX_FRAME_TRACE` 保存原始接受时间，可按各组真实采样边界计算 p95 / p99。

原版 FPS 文本在 Kool 路径中明确标记为性能 HUD，显示呈现 FPS、新画面率、引擎画面完成率和重复比例；其他后端保持原版文本。详细诊断默认关闭，轻量 HUD 计数一直开启。引擎画面完成率和原版 `currentTick` 推进率分别记录；不能将较高的引擎循环率当作呈现 FPS。

性能夹具明确区分 `combat` 和 `idle`。交战使用普通单位、正常伤害和命令，不加入无敌或补员；记录采样期存活与可见数量。伤亡后不足指定数量的结果不能宣称该数量达标。单一友军无命令的 idle 场景只验证容量，不作为持续交战成绩。

M5、1920×1080 的三个 idle 采样窗口实际保持 2250 个存活单位（原版附属单位自然创建）、至少 2135 个可见单位。呈现 119.82–119.96 FPS，新画面 119.62–119.93 Hz，重复 0–0.167%，p95 8.97–9.14 ms、p99 9.34–9.49 ms；144 FPS / 6.94 ms 目标未达成。GPU 时间为 6.45–7.13 ms、每帧约 575–581 次绘制，已接近目标预算；原生采样也观察到 MoltenVK 获取屏幕底图时的等待。测试时 Mac 锁屏、显示器休眠且配置为 60 Hz，不能据此推断唤醒后的硬件上限。

最终 v4 的单次采样诊断保持 2250 个存活、至少 2139 个可见单位，30 秒预热后采样 30 秒：呈现 119.765 FPS、新画面 119.298 Hz、重复 0.390%，p95 9.102 ms、p99 9.482 ms。原生 GPU 五秒窗口均值约 6.10–6.22 ms，仍未达到呈现目标。这是对较早运行包的单组诊断比较，并非同一运行包、重复三次的受控 A/B，也未验证视觉质量或 GPU p95；默认仍为 4 次采样。详见 [单次采样诊断](verification/vulkan-msaa1-diagnostic-2026-10-01.json)。

剩余 GPU 排查重点包括多重采样解析及全屏复制、上传使用的宽泛屏障、两个在途帧共用的目标缓冲，以及选择圆环覆盖整个矩形的透明片元开销。当前 GPU 计时包含上传、绘制、解析和复制，尚未把它们分开归因；透明顺序及所有选择标记仍须保留。

九组混编交战覆盖 661 / 1000 / 2000 初始单位，但预热期间出现正常伤亡，不能作为持续 2000 单位交战达标结果。50 ms 上传 / 呈现延迟使呈现降至约 16 Hz，同时引擎继续推进，资源驻留有界。Vulkan 使用 Swing / AWTVK 的 `CanvasWrapper`，不使用 GLFW。矩阵中的隐藏钩子操作了 JFrame，但子 Canvas 的可见标志仍为真，原生提交继续；该组不能证明停止获取交换链画面时的行为。实际最小化 / 零尺寸 / 停止获取交换链画面的情形尚未覆盖。退出时分配器仍报告并回收部分保留的 UI 资源，不能宣称无清理警告。

最终运行包（`b07d1e6f…e51d46`）完成 20.8 秒原生启动、1920×1080→1280×900 缩放、画布和窗口隐藏 3 秒、恢复及退出烟测；此前 v5 / v6 完成 40.8 / 20.7 秒同类烟测。各组均无运行异常，VMA / device / instance 正常销毁。隐藏操作附近仍可能接受已开始提交的尾部画面，窗口操作与 GPU 提交不构成原子取消边界；偏移与数量逐组保留。最终退出时仍由分配器回收 37 个缓冲和 23 张图像，明确保留清理警告。独立所有者关闭期间保持队列边界，关闭后拒绝新的模组状态修改，不恢复为前端直接执行。Android 完整 APK 已构建，尚未进行真机运行验收。

## 复现

```sh
ANDROID_HOME=/Users/wty/Library/Android/sdk ./gradlew :core:test :desktop:test :android:compileDebugKotlin

RWX_BENCHMARK_UNITS=2000 RWX_BENCHMARK_MIX=all RWX_BENCHMARK_SELECTED=1 \
RWX_BENCHMARK_MODE=combat RWX_WINDOW_WIDTH=1920 RWX_WINDOW_HEIGHT=1080 \
RWX_DESKTOP_TARGET_FPS=300 RWX_DEBUG_AUTO_EXIT_SECONDS=130 \
RWX_FRAME_METRICS=build/frame.jsonl RWX_FRAME_TRACE=build/frame.csv \
RWX_VK_METRICS=build/native.jsonl RWX_PERF_LOG=build/engine.log \
./gradlew :desktop:run -PrwxKoolBackend=vulkan \
  -PrwxRunArgs='--screen=battleroom --auto-start-battleroom'
```

混编参数为 `land-air` / `sea-air` / `all`，数量为 661 / 1000 / 2000。每组预热 30 秒，随后三次采样 30 秒。长时间测试应使用复制到独立路径的运行包，避免同时重建 Gradle 的运行 classpath。

`RWX_VK_SUBMIT_DELAY_MS`、`RWX_VK_UPLOAD_DELAY_MS`、`RWX_VK_PRESENT_DELAY_MS` 可注入测试延迟。`RWX_DEBUG_HIDE_AFTER_SECONDS` 配合 `RWX_DEBUG_HIDE_SECONDS` 配置窗口测试；必须核对实际窗口操作日志及引擎推进，不能只以计时器配置作为隐藏成功的证据。此 Swing / AWTVK 宿主的 macOS 启动命令不要添加 `-XstartOnFirstThread`，否则 AWT 焦点请求会阻塞事件线程，使隐藏和恢复只留在队列中。全部诊断默认关闭。

`-Drwx.kool.msaaSamples=1` / `RWX_KOOL_MSAA_SAMPLES=1` 可选择测试用采样数；只接受 1 / 2 / 4，默认保持 4。启动日志及原生诊断记录配置值和设备实际采样数。此选项只改变本地画面抗锯齿，不改变模拟或联机协议；单次采样的视觉质量需要另行检查。
