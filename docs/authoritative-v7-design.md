## 1. 采用的 PA 公开架构

PA 开发者公开说明了服务端独立仿真、客户端按时间取样显示、独立属性曲线、预测关键帧与后续修正、本人可见信息过滤，以及基于时间线的 ChronoCam；关键帧插值在客户端完成。[ChronoCam 技术文章](https://www.forrestthewoods.com/blog/tech_of_planetary_annihilation_chrono_cam/)、[开发者问答](https://www.forrestthewoods.com/blog/qa_planetary_annihilation_chrono_cam/)。

v7 完整采用这条公开架构：客户端复制获准接收的时间线库，服务端继续独占仿真和操作授权。位置、朝向、进度等由曲线表达；离散状态和瞬时事件分别使用 STEP 与 PULSE。客户端在一个播放时间上求值，正常播放、暂停、seek 和倒放共享这份时间线数据。

实现需要自行确定事务、量化、历史封口、恢复、资源上限和安全边界。公开文章不是 PA 私有协议的完整字节规范，本方案不声称与 PA 客户端或服务器互通。文章中的历史带宽目标也不是本项目的验收结果。

v7 不周期性回灌 v6 的完整世界 DTO 或动作面板 DTO，不把旧 Baseline/Delta 当作曲线的定时校准通道。连续属性的修正仍然是时间线事务。现有纯显示层可以临时接收由时间线求值生成的内存适配对象，但该对象不成为网络状态、回放真值或摘要输入。

### 1.1 四项硬验收门槛

下面四项是 v7 运行实现的硬验收条件，不能以“后续优化”或仅有消息格式代替。当前已有核心、真实 TLS、历史归档和网络劣化测试的分项证据，四项整体验收尚未完成。

| 门槛 | 设计要求 | 通过所需证据 |
|---|---|---|
| 大规模对局 | 以 **64 席位、65,536 个活动世界单位**作为容量设计基线；活动单位是参加真实仿真的世界单位，不是每席位各有这么多单位，也不是填满 DTO 数组 | 明确目标硬件、仿真步频和地图；实测引擎、授权观察、复制、完整哈希、归档、客户端显示的 CPU/内存/流量；分别覆盖分散可见和高重叠可见范围 |
| 慢客户端隔离 | 一个客户端读写慢、暂停读包、频繁历史跳转或恢复，不能让其他席位等待它或使仿真等待网络 | 同一对局内好连接与受限/停读连接并存，比较好连接的 tick、操作及实际呈现尾延迟；证明所有队列和暂存都有界 |
| 中途加入 | 在其他玩家继续对局时初始化新连接；原席位重连与新席位加入使用不同授权规则 | 在持续战斗中完成认证、地图、当前时间线和许可初始化，世界不暂停、不重载；新席位不能取得加入前的隐藏历史 |
| 自由回看 | 任意已获准且已归档的时间点可按需定位、暂停、倒放，再回到实时；在线窗口剪裁不能使整局历史永久不可达 | 随机跨窗口 seek、来回跳转和多窗格读取；与顺播结果一致，历史无授权扩张，实时流与当前控制不被旧历史污染 |

这是**设计容量基线，不是当前运行容量承诺**。服务器已接入 64 席位及对应地图、队伍、迷雾和中途加入生命周期；本机 64 个真实 TLS 客户端、128 个原生单位的分项检查通过。65,536 个活动单位已完成独立真实引擎测量，实时步频目标未达标；该规模下包含授权观察、复制、归档与显示的完整链路尚未通过。仅把协议队伍 ID 范围写成 0..63 不算支持 64 席位；仅通过 65,536 条合成曲线也不算完成真实引擎容量验收。测试前固定的步频和质量目标不能在结果不好时下调后仍宣称原目标通过。

## 2. 两个版本维度与三个时间水位

仿真时间与接收事务的先后顺序必须分别表示：

| 概念 | 含义 |
|---|---|
| `streamEpoch` | 当前复制流的身份；重连不能继承旧连接的对象、许可或确认账本 |
| `revision` | 已原子提交的时间线库版本，严格递增 |
| `baseRevision` | UPDATE 所基于的上一成功提交版本，必须等于 `revision−1`；RESET 从空库建立 revision 1 |
| `retainedFrom`，记为 L | 在线库承诺保留的最早时间 |
| `sealedThrough`，记为 S | 排他封口上界；`[L,S)` 内的获准历史不可再改变求值或事件集合 |
| `observedThrough`，记为 W | 此流已经发布的实际观察时间上界；更晚的数据只能是明确允许的预测 |
| `playhead` | 本地显示时间；不推进库版本、不改变水位、不参与状态摘要 |

必须满足 `0 ≤ L ≤ S ≤ W`。S 是排他边界，时刻 S 仍可被后续合法事务编辑；`[L,S)` 已封口。正常事务的三个水位不倒退，且不能以增加 L 为理由跳过尚未封口、需要归档的历史。时间采用主规范规定的整数单位与有界计算，不能把两台机器的壁钟或收到包的时间直接作为曲线坐标。

默认封口延迟目标约 5 秒，100 ms 发布间隔下在 4.9 秒触发；较短保留窗口相应缩短。实时更新、最长一秒的非恒值预测和每秒完整校验照常进行。归档按每批完整的新封口区间写入，保留小数秒尾部；结束房间时立即确认并归档剩余观察。发布线程停顿时不能承诺墙钟上限，客户端始终按实际 S 判断历史是否稳定。

同一仿真时间可以被后续事务修订，只限尚未封口的区间。比如在版本 20 发布了一个预测终点，版本 23 可以取消或替换它，但版本 21、22 必须依次提交；这不允许重写已经封口的历史。必须先按旧 S 验证全部编辑，再验证新水位并一次性提交。客户端不能用 UI 播放速度、暂停时长或自己的内存清理时机决定权威水位。

实时显示时钟根据服务器时间和单调接收时钟建立映射。对于没有获准未来数据的对象，显示时间不能越过可用观察区间。帧率下降可以跳过显示帧，不能跳过库中需要保留的生命周期和事件。

## 3. 复制库与对象生命周期

完整复制状态由已验证公开静态内容、对象时间线、事件记录、水位和协议规定的当前控制状态组成。曲线属性、值类型、对象类型和事件载荷均来自封闭 schema/catalog；网络字符串不能成为脚本、原生 ActionId、资源任意路径或客户端执行入口。

一个对象记录至少需要：

- 当前流内的不透明 incarnation，不能公开引擎全局 ID。
- 静态类型、必要显示元数据及 schema 版本。
- 披露区间与创建/结束记录。
- 按封闭属性 ID 区分的曲线集合。

“结束披露”与“确认死亡”必须区分。失去视野只能发布授权结束，不能顺便泄露隐藏对象实际何时死亡、进入哪个运输器或为何不可见。对象的历史记录可以继续存在于保留库中，但实时可选资格必须立即结束。

离开视野后再出现使用新 incarnation。升级、变形、控制或身份变化必须按主规范定义的身份边界处理，并撤销旧操作许可。历史对象仍可在旧时间被显示，不意味着其当前仍然存在或可以被操作。

对象创建、属性改变、瞬时事件和披露结束可能发生于两次网络发送之间。服务端时间线观察层必须在仿真发生这些变化时采集并保留它们，不能只扫描当前 10Hz DTO 中仍存活的单位。只出现过一个仿真步的对象或事件也不能被发送合并遗漏。

## 4. LINEAR、STEP 与 PULSE

### 4.1 LINEAR：有效区间与原始 anchors

LINEAR 段采用有效区间 `[lo, hi)`，并保存原始 `anchor0=(t0,v0)`、`anchor1=(t1,v1)`。有效区间位于原 anchors 覆盖范围内，且 `t0<t1`。在区间内用这两个原 anchors 求值：

```text
value(t) = v0 + (v1 - v0) × (t - t0) / (t1 - t0)
```

值可以是主规范声明的标量或定维向量。乘积、除法、舍入、溢出检查和角度环绕必须逐属性明确；不能让不同平台自行选择 float/FMA 或整数截断规则。量化尺度由 schema 固定，不随单次带宽压力暗中改变。

裁剪区间时只改变 `lo/hi`，保留原始 anchors。不能取边界处已舍入的值重新生成短段，否则新斜率可能使已封口区间的取样值改变。完整摘要包含实际段与原 anchors，而不是先采样成某一帧的位置后再哈希。

**修改未来终点也可能修改过去。** 若原段跨过 S，直接替换它的未来 anchor 会改变 S 之前的插值。编辑必须保留封口左侧的原段，将其有效区间裁到排他边界 S，再从 S 或更晚的未封口区间建立新段。不能仅检查被编辑 key 的时间是否大于 S。

相邻段按半开区间确定边界归属。需要真实跳变时必须显式表达边界左右值；不能以两条重叠段或修改旧历史来掩盖不连续。接收端不得通过未定义的“最后一条胜出”规则处理重叠。

缺段表示属性在该时刻不可用，不能默认保持、跨缺口插值或外推。静止使用显式恒值段，`hi=FOREVER`；LINEAR/ANGLE 恒值段的两个值相等，原终止 anchor 也可为 FOREVER。它表示最后已知值保持，不承诺未来游戏事实。全局可采样窗口和观察生命周期仍然约束呈现及当前操作资格；更新 W 不必逐对象延长相同恒值段。未显式声明的保持行为不得由渲染器补出。

### 4.2 STEP：离散状态

健康、所有权、控制状态、类型/等级、可见性、资源和动作状态等离散变化按各属性语义使用 STEP，不在相邻状态之间制造不存在的中间值。STEP 右连续；同一属性在一个时刻必须有唯一最终值，或按主规范定义的单一原子替换操作确定。

在线窗口裁剪必须保留 L 处需要的状态锚点。丢掉 L 之前的旧 key 后，不能使窗口内状态变为未知。类型、等级或所有权变化造成的旧能力撤销与显示变化必须在同一事务边界生效。

### 4.3 PULSE：瞬时事件

PULSE 至少包含稳定事件 ID、发生时间、封闭事件类型和有界载荷。事件只在实际发生且获准披露后发布；未来攻击、死亡、音效或伤害脉冲不能作为敌方预测数据提前下发。

正常向前播放在 `(上次播放时间, 当前播放时间]` 查找事件，按稳定 ID 去重。暂停不重复触发，seek 和倒放不执行音效、命令、资源变化或其他副作用。需要回看爆炸等显示效果时，以事件时间、寿命及种子进行纯显示求值；事件不调用仿真、AI、脚本或原单位 update/draw hooks。

PULSE 的播放游标属于本地状态，不进入完整库摘要。事件记录本身的 ID、时间和载荷进入摘要及归档。

## 5. 事务、合并与量化修正

事务可以包含创建/结束披露、曲线区间替换/删除、事件插入/删除、控制许可变更和水位推进。编辑必须指向当前 incarnation 与精确 base，给出不歧义的区间和版本。引用不存在的对象或属性、无法按规定顺序解析的操作冲突以及越过封口边界均须拒绝。空区间内容的 splice 和同事务多次有序修订按主规范处理，不能另行规定隐式合并规则。具体错误分类由主规范固定。

客户端在暂存副本上验证：对象引用、曲线类型、区间覆盖、重叠、记录唯一性、量化范围、时间水位、终局和容量全部通过后，才把整个新 revision 发布给显示层。一个事务可以把旧未来段截断，并加入修正段和新预测段；接收者不能先看到删除、下一帧再看到替换。

发送合并以最后成功写出的库版本为 base，生成一个 `revision=baseRevision+1` 的新事务，写成功后才提交。尚未写出的中间包可以丢弃，但其中仍属于保留区间的对象历史、曲线、事件和披露区间必须存在于最终库里。不能复用 v6 的“只保留当前活单位快照”来代替时间线库。

事务 revision 和 curveRevision 属于实际发送的复制状态，不是仿真观察器全局计数。合并掉的源修改不能造成事务跳号；每条曲线的修订按实际提交的 splice 次数递增，包括同事务中的多次 splice。源库版本、网络库版本和归档时间片版本需要明确映射，不能直接共用一个计数器。

预测器与仿真器是两层。服务器用真实仿真观察误差并决定是否发布曲线修正；复制模型的量化值与原浮点仿真值之间允许的误差必须预先声明。哈希一致不能证明显示坐标逐位等于原始浮点坐标。

仅将原值和预测值分别量化并不能保证两者落入同一量化格，尤其在格边界附近。服务器必须维护实际成功发送的同一量化曲线模型，并与客户端对这份模型校验；不能在检查时临时量化当前引擎状态后要求它与旧预测摘要相等。

## 6. 未来数据、历史权限与当前控制

敌方对象的实际观察只发布当前及已经获准的历史数据，不下发由隐藏世界决定的真实未来路线、寻路点、目标、秘密事件或披露结束时间。主规范允许明确标记、有界且仅由已披露历史推导的运动预测；这种预测是可撤销的显示假设，不能当作未来事实。已经发出的未来秘密不会因删除关键帧而从恶意客户端消失。未来有效期和预测权限必须按对象、属性和披露角色校验，不能只设置一个全局最大预测时长。即使有效区间已裁在 W 以内，原始 anchors 仍完整出现在载荷中，其时间和值也必须获准披露；普通观察与获准预测分别审核，不能只检查 `lo/hi` 就把带有未来秘密的 anchor 发出去。

己方可允许的预测也只能由已授权数据产生。直接使用包含隐藏碰撞、隐藏目标或隐藏路径约束的引擎内部计划，仍可能产生信息泄露。当前私有控制许可不能从预测到达、未来建造完成或历史可见性推导出来。

时间线历史与当前控制许可分离：

- 历史库回答某个时间点可以显示什么。
- 当前许可回答此刻可以选择、发令和引用哪些目标。
- 历史 incarnation、已结束的能力、旧事务版本和旧许可 generation 都不能恢复操作资格。
- 失去视野、失控、装载、变形、终局和重同步立即撤销对应实时操作，并使已排队的旧输入失效。
- ChronoCam 暂停、倒放或回看历史时，默认只读；回到实时显示后再建立当前选择和许可。

本地选中框、播放游标和显示插值不属于服务器权威库。动作描述可以来自服务端批准的静态 presentation/schema 与实时动作状态；客户端仍不得加载 INI、TMX、脚本或全量世界来生成能力。

若需要归档历史动作显示，只归档当时获准的只读描述和状态，不把可执行许可当成回放授权。当前控制状态和历史归档的摘要范围须在主规范中分别明确，不能由实现自行跳过某一类字段。

## 7. 每秒完整库校验与恢复

每个有效 LIVE 流按单调时钟约 1Hz 重新遍历完整私有库。静止、暂停显示及终局不能停止网络确认；UI playhead 不改变被检查的状态。HISTORY 流在完整 RESET 后检查一次，正确确认后发送完成的 StreamEnd；已经结束的历史流可继续本地取样，但不再周期检查或接收操作/恢复请求，新的历史窗口通过新请求取得。摘要覆盖主规范列出的全部实际静态内容、保留对象、生命周期、曲线、原 anchors、事件、当前复制控制状态及水位。不能用缓存地图摘要、最近一个补丁、当前采样帧或显示坐标替代完整输入。

规范必须固定摘要域、排序、整数/量化编码与集合表示。允许几何意义相同但记录不同的曲线时，它们仍是不同的复制状态；客户端必须保留收到的规范记录，不能为显示优化私自重拟合参与哈希的库。

服务器只检查最后成功写出并提交的库 revision，不能检查尚在合并槽中的版本。检查和 ACK 引用 epoch、检查序号与精确 revision；账本有界，并处理“ACK 比写后登记更快”的竞态。网络读写锁不能阻塞仿真发布线程。

发现缺 base 或摘要失配时，客户端立即禁用依赖失效状态的操作，并进入完整时间线基线恢复。坏摘要的实际 ACK 本身触发一次隐式恢复，不能再叠加一份同义请求制造重复基线。等待期间合并重复恢复需求；不能发送伪造的成功摘要。

恢复基线包含整份当前保留库、水位和必要静态内容引用，不包含周期 v6 DTO 锚点。它可以分块传输，但必须有唯一传输身份、总数量/总字节上限、块序号、最终验证和绝对完成期限；接收过程中旧输入已撤销，新库在最终提交前不可操作。

确认与恢复须有独立期限和连续失败预算，保活、不断重发基线或时间推进不能无限续期。新流、撤销和恢复后的迟到 ACK 不得触发反复恢复。具体数值由主规范统一给出，必须通过慢连接和并发测试，不能因为“使用曲线”取消这些边界。

## 8. 有界在线库与独立整局归档

在线内存同时受时间窗口、对象数、曲线/段数、脉冲数、事务操作数和实际字节预算约束。只有时间窗口上限不足以保证有界：大量对象每仿真步转向时，短窗口也可能产生极大记录量。预算还应考虑 JVM 对象开销、索引、暂存基线和 GPU 显示副本，不能把线上编码字节数当成全部内存。对象与事件 ID 的不复用也必须有有界验证机制，例如纳入 RESET/摘要的单调分配高水位，不能靠永不清理的墓碑集合满足。

服务端通过显式事务推进 L 并裁剪在线历史：

- 保留 L 处需要的 STEP 状态。
- LINEAR 跨越 L 时裁剪有效区间并保留原 anchors。
- 只有按规范已过期且不再被窗口内显示需要的对象、事件及元数据才能移除。持续特效需要保留 carry-in 来源或等价的活跃效果记录，例如 t=9.8 的一秒爆炸在窗口从 10 开始时仍应显示；独立回放片同样需要跨界效果。
- 相同裁剪必须在服务端成功发送状态与客户端私有状态中一致发生。
- 不能静默删当前获准活对象来满足容量；无法维持已承诺限额时须明确处理，不能生成貌似完整的截断库。

整局归档独立接收已授权时间线，保留完整历史；在线剪裁不能顺便删除归档。历史较远时按时间片和索引加载，内存仍然有界。若提供在线 ChronoCam 历史请求，应使用明确隔离的历史切片/读取上下文，不将旧切片回灌为当前实时库，也不能借历史请求恢复当前控制许可。

归档按席位和实际授权范围构建。不同席位历史不能合并为客户端可请求的隐藏全世界；重连是否允许取得旧连接历史必须由身份与授权策略明确定义，不能从“同一个teamId”自动推导。

### 8.1 仿真发布与慢客户端隔离

仿真线程不得等待 socket、慢客户端、历史下载、归档 I/O、完整哈希或网络确认。观察数据通过有界的不可变发布边界交给复制与归档层；授权过滤、采集和复制本身的 CPU 开销仍必须计入仿真预算，不能因为没有阻塞调用就称为零成本。

每个连接有独立 writer、字节预算和有界发送/恢复队列。历史请求、分块基线和哈希工作也受每连接及全服务器的并发、内存和 CPU 上限约束；不能创建无界后台任务把慢连接的成本转移成全局 CPU/内存饥饿。共享公开不可变资源可以减少复制，但不能共享可变席位私有状态或绕过授权过滤。

慢客户端赶不上当前窗口时，可以取消未完成的旧发送，进入新 epoch 的完整 checkpoint/RESET，而不是积累无限差量。客户端在完整新库提交前停止操作，旧输入和旧 ACK 失效。正常客户端仍按自己的发送与仿真节奏前进；不能使用全员 ACK 屏障。

checkpoint 赶上策略只替换该连接的在线窗口，不丢弃独立整局归档。归档在封口数据离开在线库之前接收完整获准历史，并通过检查点和持久进度保证归档的可用范围。磁盘与归档吞吐是硬资源条件：容量不足时须明确拒绝、报告归档失败或按预定策略结束，不能静默丢历史又声称满足自由回看，也不能无限阻塞仿真等待存储恢复。

### 8.2 中途加入与重连

新连接的认证、地图加载、时间线快照、追赶和许可建立在其他玩家继续仿真时完成，不暂停世界、不重载地图、不重置其他席位。客户端完成当前有效 RESET 并追赶到可接受的 LIVE 收据后才可操作。传输期间世界继续变化，必须从该 checkpoint 的成功版本补发连续 UPDATE，或在已落后窗口时改用新的 checkpoint；循环重置有界，无法追赶时明确结束该连接。

必须区分两条接入路径：

- **原席位重连**：验证该席位凭据，建立新 session/epoch/controlEpoch 和当前观察身份。是否承接旧连接历史须依据保存的原授权范围；不能仅凭客户端声称的 teamId 承接，也不能继承旧操作许可。
- **新席位中途加入**：先完成队伍、初始单位、迷雾和胜负参与规则的服务端初始化，再从加入时刻建立其观察。默认历史下界不早于加入时刻；当前看到的对象不能补出加入前的隐藏轨迹、生产或战斗。若允许更早公开资料，必须有独立明确的公开授权规则。

64 席位初始化和中途加入不能依赖当前固定双人地图的出生点、队伍循环或“等所有配置玩家到齐才 tick”的启动约定。新席位的创建、资源及胜负规则本身也须通过真实引擎验证。

### 8.3 自由回看与实时流并存

自由回看要求任意已授权、有记录的时间点都可定位并按需加载，不要求把整局装入内存，也不承诺远程历史瞬间下载完成。超过单个 HISTORY 窗口上限时按独立封口片分次读取；窗口外历史仍在归档中可达。客户端应缓存有限时间片，保持实际呈现范围和缺片状态明确。

历史流加载、seek 和回放暂停不阻塞 LIVE 仿真或让当前流退回旧水位。历史流正确确认一次并结束后可继续本地取样；切换到另一个时间区间建立新历史请求。历史窗口、当前选择与当前操作许可分开，回看与实时多窗格并存时只能由明确的实时窗格发令。

## 9. 自包含回放、seek、暂停与倒放

新回放格式独立于当前格式 2 的 v6 DTO 回放。文件包含实际公开静态地图、schema/catalog 版本、时间尺度、授权身份范围、时间线数据、封口水位、索引和完成标记。读取不依赖网络服务器、外部地图缓存、原始地图脚本或引擎仿真。

默认回放语义是**最终封口的授权历史**。它不是“当时收到预测包时用户恰好看见什么”的网络体验录屏；后者需要另行定义接收版本与播放时钟，不能混为一种 seek 结果。

seek 到 T 不能只找到 `serverTime ≤ T` 的最后一个事务就停止。后来提交的事务可能修改未封口的 T。主规范采用已封口、可独立加载的授权时间片：索引直接定位包含 T 的完整片段，保留求值所需边界和原 anchors。内部归档若先存修订日志和检查点，须应用所有涉及 T 的修订，直到 `sealedThrough > T`，再最终化该时间片；目标 T 恰好等于排他 S 时仍未封口。

最终化前需要确保 T 的数据没有在检查点中先被在线剪裁。只有客户端实际收到的数据时，录制器不能承诺补出未收到的历史；缺片、重连或越过窗口的恢复必须记录可用范围及 gap，或从获准归档补齐后再声明完整。

暂停仅停止 playhead。倒放和 seek 从时间线纯求值对象、属性和显示效果，不执行脉冲副作用、重新发命令或初始化游戏仿真。求值结果不依赖之前从哪个方向到达 T；直接 seek、顺播到达及倒播到达应得到相同的离散状态和规范曲线值。

终局需要固定最终观察时间，裁掉不再成立的预测，封口并正常结束归档。截断、错误索引、缺片、非法修订和没有完成标记都必须如实报告，不能标作正常完整回放。

## 10. 迁移实施顺序

1. **冻结模型。** 完成 v7 主规范、属性 schema、量化/舍入、时间水位、生命周期、编辑区间、摘要和限额。先用小型反例证明封口与替换语义，不接真实网络。
2. **纯时间线库。** 实现事务构建、原子 applier、剪裁、任意时间求值、完整哈希和独立编码向量。覆盖原 anchors 裁剪、断点、同时间 STEP/PULSE、版本错误与溢出，并证明容量限制包含暂存副本和工作队列。
3. **仿真观察层与容量。** 从真实仿真采集生命周期和事件，不依赖 10Hz 当前 DTO 扫描。解除当前固定地图/双席位限制，验证引擎队伍、单位、迷雾与中途加入生命周期。把授权过滤置于所有曲线、预测和归档输出之前，验证隐藏状态等价及 64 席位/65,536 活动世界单位设计基线。
4. **传输与恢复。** 接入成功写后提交、发送合并、1Hz 完整检查、ACK 账本、完整时间线基线和有界分块恢复。先用真实 TCP/TLS 验证，无图形验收。
5. **只读显示。** Kool 从时间线求值绘制，保持静态资源白名单和无本机引擎约束。分别测试 live、暂停、seek 和倒放；当前操作始终引用实时许可。
6. **整局归档。** 实现自包含文件、封口索引、随机 seek、gap 与截断处理，再接 ChronoCam 控件。历史加载不影响当前实时库摘要或操作 generation。
7. **同场景与硬门槛测量。** 对冻结 v6 产物与 v7 候选运行双方均支持的相同授权状态、操作脚本和网络条件，完成下节矩阵；超出 v6 当前双人限制的容量场景另外验收，不伪造同规模 v6 实测对照。完成四项硬门槛后才可声明目标通过。性能未达标时修改模型或实现，不能先填写收益。
8. **发布决策。** 正确性、隐私、资源和性能证据齐备后再决定应用版本及 v7 上线范围。v7 不在 wire6 连接里静默切换；原版兼容模式继续独立。本文交付本身不执行版本升级。

### 11.1 带宽计算与公平比较

分别统计初次静态地图/缓存握手、首次完整库、稳态事务、曲线修正/删除、事件、迷雾、当前动作状态、检查/ACK、历史请求与恢复。稳态下行、上行和主机总上行分别报告；同时注明是否包含 TCP/IP/TLS，不能混合不同测量层。

可用下面的关系解释结果，但不能用理论估算代替实际编码字节：

```text
稳态字节 ≈ 新段字节 × 新段频率
         + 修正/删除字节 × 修正频率
         + 生命周期/事件/迷雾/动作状态
         + 完整检查与确认
```

曲线在稳定运动和稳定进度上有减少更新的机会；频繁改变方向、碰撞、资源波动和战斗可能需要大量修正。若仍在每个发布周期为每个移动对象发送更大的新段，流量可能高于 v6 单字段差量。

v6 与 v7 必须使用相同场景、相同授权范围、相同显示误差目标与可比较更新质量，包含各自真实恢复及检查成本。纯合成库使用完全相同的输入轨迹；真实引擎比较使用相同地图、单位与操作脚本，并验证结果差异未使某端少看对象或少执行事件。无真实大规模样本时，只能报告合成结论。

最终报告应同时填写绝对值和相对变化。收益一栏在相关正确性与误差约束通过、实际测量完成前保持“未测”；没有通用“PA 曲线必省若干倍”的承诺。

### 11.2 延迟与误差须同时报告

带宽不能通过任意增加显示滞后、扩大位置误差或延后披露来换取而不说明。预先固定各属性的量化尺度、最大预测期限、修正阈值及显示缓冲策略，再比较延迟分布和流量。若改变这些参数，视为另一组实验。

服务器仿真、事务发布节奏和客户端显示帧率分别测量。1Hz 完整检查不应成为每条正常操作的往返闸门。输入预测、服务器提供的获准未来段和纯显示插值是三种不同机制，结果中必须注明实际使用哪一种。

无丢包/无积压的代码推导不能替代 WAN 测量。GPU 实际呈现、OS 输入调度、带宽不足产生的排队和 TCP 重传均会改变尾延迟；应使用可关联的命令 ID、服务器应用时间、事务版本及实际呈现探针测量，而不是仅记录 render submit。

## 12. 发布前必须关闭的风险

- 未来 key 修正是否确实保持 S 之前的历史，尤其是量化边界、断点和角度跨零。
- 快速创建/结束及瞬时事件是否被仿真观察层遗漏，或被网络合并误删。
- 历史可见对象是否可能通过旧许可、倒放选择、恢复或重连变成当前可操作对象。
- 整库哈希是否实际包含保留历史、未来段、静态内容和规定的控制状态，且与 playhead 无关。
- 在线裁剪、恢复基线和整局归档之间是否存在未声明的历史缺片。
- 最坏曲线 churn、原 anchors 保留、分块基线与索引暂存是否满足真正的内存/CPU 上限；64 席位/65,536 活动世界单位及另外三项硬门槛是否实测通过。
- 所有收益是否来自同场景、同授权和同误差目标的真实数据；当前 wire6 验收不能代替 v7 验收。

运行实现与分项验证正在进行。任何待定字段、上限、误差预算或回放表示都应在主规范冻结前解决，不以“PA 也是这样”替代项目自身的正确性与测量证据。
