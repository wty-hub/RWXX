### 状态库实施前确认的问题记录

B1–B4 已由后续 r1 修订闭合。容量最终选择第 10.1 节第 **3、4、5** 项（包括水位和修订等元数据，排除域前缀、身份字节和地图），不是下文最初建议的仅第 4、5 项。STEP 段起点不晚于 observedThrough、终局值 finishedAt 不晚于该段 lo、所有 PULSE 不得来自未来、未知 optional 不允许预测、单曲线同一 time 最多 4096 个 pulse 也已明确。以下保留发现与修订理由，不能再解读为未修问题。

实现时另确认：UPDATE 的编辑起点不得早于新 retainedFrom，避免修改窗口之前的 carry-in 脉冲而间接改变窗口内效果；零尾效事件恰位于 retainedFrom 时仍保留，只有时间已经严格早于窗口起点且尾效也已结束时才能移除。网络 HISTORY 的关系与覆盖按其历史片检查，不要求 observedThrough 处存在当前操作面板。

**B1：RESET 初始化与历史关闭。** 第 5.3 节要求按旧 sealedThrough 校验，第 6.5 节禁止关闭时间早于旧 sealedThrough，但 RESET 从空库恢复时尚没有旧水位。应明确 RESET 暂存库的初始封口为 0，或者明确旧封口限制仅对 UPDATE 生效；完整恢复对象、曲线和关闭记录后，再检查声明的新封口及最终不变量。否则把 Begin 的新封口当成暂存库起点，会错误拒绝合法的已结束历史观察。

**B2：普通段不能绕过未来预测边界。** 第 6.3 节目前只限制“非恒值预测端点”。需要明确 flags=0 的非恒值锚点不能伸入尚未观察的未来，例如要求 anchor1Time≤observedThrough；flags=1 才允许在 maxPredictionTime 内使用未来端点。恒值最后已知值保持是明确例外。应同时明确已登记资源、控制、库存、能力及胜负属性不得以预测状态提前生效；服务端仍须独立证明预测只依赖获准披露数据。

**B3：RESET 脉冲必须允许分批恢复。** 第 6.4 节只有“首次 PulseSplice”允许装入不超过声明高水位的既有事件，随后按普通新事件规则。单次事件上限为 4096，因此一条曲线保留超过 4096 个事件时无法恢复。应在整个 RESET 初始化阶段允许按多次 splice 装入既有事件，并跨批检查事件 ID 唯一、值合法、均不超过声明高水位；不能放宽 UPDATE 的旧 ID 禁止复用规则。

**B4：确定性裁剪与容量。** 明确 RetainFrom 和 ObservationClose 裁剪是否递增曲线修订号，建议不递增，只有 splice 递增。每流 64 MiB 持久容量应给精确公式，例如第 10.1 节第 4、5 项规范编码的完整字节数（包括 objectCount，不包括地图及固定上下文），使不同实现对同一库得到相同限额结论。

对象/事件高水位及 carry-in/maxTailTime 已加入规范；它们关闭了原先有界防复用和跨窗口效果的设计缺口，仍需由分批 RESET、RetainFrom 与独立历史片测试验证。

## 需确定的附属一致性规则

- 明确 canonicalMapRecord.resourcePools 是否必须与 terrain 的资源点 bit 完全一致；否则地图中存在两个互相冲突的资源点来源。
- 明确未登记的 1..65535 属性是否一律拒绝；当前“保留”与“未知 optional 属性仍通用保存”之间存在解释空间。
- 明确 ROOT 必备属性的覆盖要求、UNIT 必备属性在观察区间与保留窗口交集上的完整覆盖，以及 PANEL.selection 与 subjectHandle、ROOT.selection 的一致性。空洞不应被客户端自行解释成对象不存在。
- 明确每流 64 MiB 持久状态的精确计数字节范围；规范摘要串包含地图，而容量条款又排除地图，需要同一可机械检查的公式。
- 明确关闭流后迟到 CheckAck 与已结束 HISTORY 的 Restore 如何处理；不得复活旧流或重新授予控制。

## 已由另一审查同步给主规范作者的关联问题

以下不重复作为新问题提出，但应随主规范一起验收：

- RetainFrom 或独立历史片起点之前发生、寿命仍延续到窗口内的效果，不能因简单删除所有旧 pulse 而丢失；需要确定的 carry-in 表示。
- 对象句柄与 pulse eventId 的“不复用”需要有界且可恢复的防复用状态；裁剪后不能仅依靠已被删除记录判断，应有高水位等参与 RESET 和摘要的机制。

## 公开依据的边界

[ChronoCam 原文](https://www.forrestthewoods.com/blog/tech_of_planetary_annihilation_chrono_cam/)描述曲线、step/pulse、预测修订及停止隐藏对象更新；[Q&A](https://www.forrestthewoods.com/blog/qa_planetary_annihilation_chrono_cam/)补充客户端采样等设计。两篇没有公开可复刻的完整线格式。本规范的字段、TLV、时间刻度、边界和恢复机制属于自定义协议选择。
